# v2.0.0 효율화 설계

## 비용을 줄이는 단위

1. 공식 자료는 변경하지 않는 데이터 층으로 보관한다. 611개 문장·해설·성취수준을 모델에게 반복 작성시키지 않는다. 공식 PDF를 로컬에서 한 번 읽어 코드별 출처 위치를 색인하고 파일 해시로 재사용한다.
2. 승인된 10개 사례는 기준별 예외 데이터로 유지한다. 나머지는 교과의 설계 관점과 성취기준에 실제 나타난 수행(비교·설명·표현·문제 해결·실천 등)을 연결하는 작은 규칙 집합을 공유한다. 규칙 선택 이유와 교사가 확인할 범위를 표시한다.
3. 실제 내용을 확인하지 않은 개념 관계는 단정문으로 꾸미지 않는다. 근거가 있는 사례는 관계 가설, 공통 조합은 교사가 검토할 관계 탐구 방향으로 구분한다. 사실·개념의 구별, QFT, 교사 선택·성찰 틀은 공통 UI에서 제공한다.
4. 화면과 MD·Word·평가 CSV는 같은 설계 객체를 사용한다. 별도 모델 호출·중복 생성 없이 로컬에서 조합한다. 원문 인용과 설계 제안은 구분한다.
5. 원래 영역명과 내용 체계명이 일치하면 이름 일치 연결로 표시한다. 단원→영역 연결은 증거 단어와 대안을 표시한 제안으로 취급한다. 신뢰가 낮으면 연결 보류 또는 후보만 제시한다. 교사의 기존 선택은 우선 보존한다.
6. 공통 규칙을 바꾸면 전체에 반영한다. 검증된 예외만 작은 데이터로 추가한다. 캐시는 기준 코드·영역 선택을 키로 하여 선택 변경 시 재계산한다.

## 적용 순서와 완료 조건

공식 출처 색인 → 공통 규칙/원본 통합 → 611개 구조·원문·내보내기 검사 → 대표 교과 UI·저장·모바일 검사 → 버전/인수인계/변경 기록 → 기존 GitHub 브랜치 반영 및 게시본 확인.

611개에 공통 설계 구조를 적용한 것과 611개 수업안을 교사가 개별 검토한 것은 다르다. 화면에서 승인 사례·규칙 기반 초안의 차이를 표시한다. 배포에는 재현 가능한 빌드 소스, 원문 자료, 테스트를 포함하며 기존 게시 주소를 유지한다. 기존 로컬 저장값을 삭제하지 않는다.

버전은 v2.0.0. 개별 생성 601회 대신 소수의 교과·수행 규칙과 예외 데이터로 구현하며, 앱 이용 시 AI 호출은 없다. 이 작업의 정확한 모델 토큰 수가 제공되지 않으면 추산을 실측처럼 제시하지 않는다.
